## Objective

Create the `clickup` Python package directory and its data models so later tasks have a
buildable package to extend. Produces the connection, scope-config, tool-scope, and task
tool models.

## Files

- **Create** package dir `backend/python/plugins/clickup/` with:
  - `pyproject.toml`, `build.sh`, `run.sh` (copied/adapted from `azuredevops`; keep
    `pydevlake = { path = "../../pydevlake", develop = true }`).
  - `clickup/__init__.py`
  - `clickup/models.py` — `ClickUpConnection`, `ClickUpScopeConfig`, `ClickUpFolder`,
    `ClickUpTask`.
  - `tests/__init__.py`
- Create empty `clickup/streams/__init__.py` so the package layout matches azuredevops.

## Implementation notes

- Implement the exact model fields/types in tech design §1.5 (token `SecretStr`,
  default endpoint & `rate_limit_per_hour`; the three optional `re.Pattern` fields on the
  scope config; `ClickUpFolder` extra fields; `ClickUpTask` `source=` JSON pointers).
- ClickUp date fields arrive as **epoch-millisecond strings** — add the `@validator` on
  `ClickUpTask` that converts them to `datetime` (tech design §1.5 note).
- Match `azuredevops/models.py` for base classes, imports, and the ASF header.
- Do **not** add the migration here (that is T5) and do **not** add API or stream logic.

## Definition of Done

- `poetry install` / `build.sh` succeeds for the new package; `import clickup.models`
  works.
- Unit test covering the epoch-ms → `datetime` validator (valid string, `None`/missing
  optional field) — mirrors the date-parsing coverage called for in tech design §1.6.
- No existing plugin is affected.
