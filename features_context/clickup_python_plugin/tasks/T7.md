## Objective

Implement `clickup/main.py` — the `ClickUpPlugin` entrypoint that ties the connection,
scope config, tool scope, API client, and the `ClickupTasks` stream together and exposes
the CLI surface. This completes a runnable plugin.

## Files

- **Create** `backend/python/plugins/clickup/clickup/main.py`.

## Implementation notes

- `ClickUpPlugin(Plugin)` declaring `connection_type=ClickUpConnection`,
  `tool_scope_type=ClickUpFolder`, `scope_config_type=ClickUpScopeConfig`, and
  `streams` returning `[ClickupTasks]`.
- `test_connection`: `GET /team`; map HTTP 401 → "Invalid ClickUp personal API token"
  (`clickup_invalid_token`), return `TestConnectionResult` (tech design §1.2 error
  handling, §1.4 errors).
- `remote_scope_groups`: `GET /team` then `GET /team/{id}/space` → `RemoteScopeGroup`
  with id `team/space` (tech design §1.2-A).
- `remote_scopes(connection, group_id)`: `GET /space/{id}/folder` → `[ClickUpFolder]`.
- `domain_scopes(folder)`: yield one `Board` per Folder; Board id must match the board id
  the stream (T6) uses for `BoardIssue` / `Incident.scope_id`.
- Plugin must be startable via `fire` (`if __name__ == ...: ClickUpPlugin.start()`),
  matching `azuredevops/main.py` and its ASF header.

## Definition of Done

- `run.sh` / `python -m clickup.main plugin_info` works; the plugin reports its streams.
- Integration tests (tech design §1.6) against recorded ClickUp responses: success
  `test_connection`; `401 → invalid-token` result; `remote_scope_groups` and
  `remote_scopes` parse fixtures into the expected groups/folders.
- End-to-end import chain (`main` → `streams` → `api` → `models` → `ticket`) loads with
  no import errors; existing plugins unaffected.

## Development progress

**Status: DONE.**

Implemented `clickup/clickup/main.py` with the `ClickUpPlugin(Plugin)` entrypoint,
completing a runnable plugin.

- **Type wiring:** `connection_type=ClickUpConnection`, `tool_scope_type=ClickUpFolder`,
  `scope_config_type=ClickUpScopeConfig`, `streams=[ClickupTasks]`.
- **`test_connection`:** `GET /team` via `ClickUpAPI.teams()`; catches `APIException` and
  maps HTTP 401 → `"Invalid ClickUp personal API token"`; returns
  `TestConnectionResult.from_api_response(res, message)` (tech design §1.2 error
  handling, §1.4).
- **`remote_scope_groups`:** `GET /team` → for each team `GET /team/{id}/space`; yields one
  `RemoteScopeGroup` per (team, space) with id `"{team_id}/{space_id}"` and the space name
  (tech design §1.2-A).
- **`remote_scopes(connection, group_id)`:** splits `group_id` into team/space, `GET
  /space/{space_id}/folder` → yields `ClickUpFolder` per folder (carrying `space_id`,
  `space_name`, `team_id`).
- **`domain_scopes(folder)`:** yields one `ticket.Board` per Folder; the framework assigns
  `board.id = folder.domain_id()`, which equals the `ctx.scope.domain_id()` the T6 stream
  uses for `BoardIssue.board_id` / `Incident.scope_id` (verified by a test asserting
  `clickup:ClickUpFolder:<cid>:<folder_id>`).
- **CLI:** `if __name__ == '__main__': ClickUpPlugin.start()` (fire), matching
  `azuredevops/main.py` + ASF header.

**Tests:** `clickup/tests/plugin_test.py` (8 tests) — `assert_valid_plugin`; streams
expose `ClickupTasks`; `test_connection` success and `401 → invalid-token`;
`remote_scope_groups` parses teams/spaces into `"team/space"` groups; `remote_scopes`
parses folders into `ClickUpFolder`s; `domain_scopes` yields a `Board` per folder; board
id matches the stream board id. The API is faked via `monkeypatch` on
`clickup.main.ClickUpAPI`. Full plugin suite: **50 passed** (8 new + 42 existing), no
regressions.

**Verification:** `ClickUpPlugin().plugin_info()` runs cleanly and reports name `clickup`,
the `ClickupTasks` stream (Collect/Extract/Convert subtasks), tool table
`_tool_clickup_clickuptasks`, connection/scope-config tables, and 1 migration script. The
end-to-end import chain (`main → streams → api → models → ticket`) loads with no import
errors. (Direct `run.sh plugin_info` over the CLI cannot be exercised on Windows because
the IPC output uses inherited fd 3, which the Go host supplies; `plugin_info()` itself
executes successfully.)
