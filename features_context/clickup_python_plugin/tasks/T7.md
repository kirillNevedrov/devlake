## Objective

Implement `clickup/main.py` — the `ClickUpPlugin` entrypoint that ties the connection,
scope config, tool scope, API client, and the `ClickupTasks` stream together and exposes
the CLI surface. This completes a runnable plugin.

## Files

- **Create** `backend/python/plugins/clickup/clickup/main.py`.

## Implementation notes

- `ClickUpPlugin(Plugin)` declaring `connection_type=ClickUpConnection`,
  `tool_scope_type=ClickUpFolder`, `scope_config_type=ClickUpScopeConfig`, and
  `streams` returning `[ClickupTasks]`.
- `test_connection`: `GET /team`; map HTTP 401 → "Invalid ClickUp personal API token"
  (`clickup_invalid_token`), return `TestConnectionResult` (tech design §1.2 error
  handling, §1.4 errors).
- `remote_scope_groups`: `GET /team` then `GET /team/{id}/space` → `RemoteScopeGroup`
  with id `team/space` (tech design §1.2-A).
- `remote_scopes(connection, group_id)`: `GET /space/{id}/folder` → `[ClickUpFolder]`.
- `domain_scopes(folder)`: yield one `Board` per Folder; Board id must match the board id
  the stream (T6) uses for `BoardIssue` / `Incident.scope_id`.
- Plugin must be startable via `fire` (`if __name__ == ...: ClickUpPlugin.start()`),
  matching `azuredevops/main.py` and its ASF header.

## Definition of Done

- `run.sh` / `python -m clickup.main plugin_info` works; the plugin reports its streams.
- Integration tests (tech design §1.6) against recorded ClickUp responses: success
  `test_connection`; `401 → invalid-token` result; `remote_scope_groups` and
  `remote_scopes` parse fixtures into the expected groups/folders.
- End-to-end import chain (`main` → `streams` → `api` → `models` → `ticket`) loads with
  no import errors; existing plugins unaffected.
