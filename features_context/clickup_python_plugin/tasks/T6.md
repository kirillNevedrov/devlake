## Objective

Implement `clickup/streams/tasks.py` — the single `ClickupTasks` stream that collects
ClickUp tasks (incrementally, with pagination + 1-day overlap), extracts them to the
`ClickUpTask` tool model, and converts each into a DevLake `Issue` (+ `BoardIssue`,
`IssueAssignee`) and, for incidents, an `Incident` (+ `IncidentAssignee`). This is the
core of the feature.

## Files

- **Create** `backend/python/plugins/clickup/clickup/streams/tasks.py`.

## Implementation notes

- **collect** (tech design §1.2-B/C, §1.3 "Incremental cutoff"): for the Folder scope,
  list its Lists then page each List's tasks ordered by `updated asc`/`reverse=true` per
  the endpoint in T4. First sync / full re-sync → no date filter; incremental →
  `date_updated_gt = last_updated_ms − 86_400_000`; track high-water mark
  `max(date_updated)` in state. Use the `ctx.incremental` flag like azuredevops.
- **extract**: rely on the tool model `source=` pointers + the epoch-ms validator from
  T2 (use `autoextract` as azuredevops does).
- **convert** business logic — implement exactly per tech design §1.3:
  - type classification via the three compiled regexes, case-insensitive, precedence
    INCIDENT > BUG > REQUIREMENT, default REQUIREMENT, empty patterns → all REQUIREMENT;
  - status mapping (`status.type` → TODO/IN_PROGRESS/DONE/OTHER, preserve original);
  - resolution date (`date_done` fallback `date_closed`); lead-time minutes;
  - issue key (`custom_id` else `id`); subtask/parent linkage;
  - emit `Issue` + `BoardIssue` (board id from Folder scope) + `IssueAssignee` per
    assignee; when type == INCIDENT also emit `Incident` (+ `IncidentAssignee`) with
    `table="boards"` and `scope_id` = board id.
- Use `domain_id(ClickUpTask, connection_id, task.id)` for domain ids; Board id derives
  from the Folder scope (consistent with T7's `domain_scopes`).
- `domain_types = [DomainType.TICKET, DomainType.CROSS]`,
  `domain_models = [Issue, BoardIssue, IssueAssignee, Incident, IncidentAssignee]`.

## Development progress

**Status: DONE.**

Implemented `clickup/clickup/streams/tasks.py` with the single `ClickupTasks` stream
(`domain_types = [TICKET, CROSS]`, `domain_models = [Issue, BoardIssue, IssueAssignee,
Incident, IncidentAssignee]`).

- **collect**: lists the Folder scope's Lists (`api.lists(folder.id).json['lists']`),
  then iterates each List's tasks via the framework `ClickUpPaginator` (auto-pagination).
  First sync / full re-sync (`ctx.incremental` false) → no date filter; incremental →
  `date_updated_gt = last_updated − 86_400_000` (1-day overlap). Tracks the high-water
  mark `max(date_updated)` across all lists and emits it per task as
  `{'last_updated': ...}` state. Cutoff logic extracted to the static helper
  `ClickupTasks.incremental_cutoff` for direct testing. Logs cutoff and list counts.
- **extract**: inherits the framework `autoextract` (tool-model `source=` pointers +
  the epoch-ms `@validator` from T2).
- **convert**: module-level helpers `classify_type` (precedence INCIDENT > BUG >
  REQUIREMENT, default REQUIREMENT, empty patterns → REQUIREMENT), `map_status`
  (`open`→TODO, `custom`→IN_PROGRESS, `closed`/`done`→DONE, else OTHER; preserves
  original), `compute_lead_time_minutes` (`date_done − date_created`). Issue key =
  `custom_id` else `id`; subtask/parent linkage via `domain_id(ClickUpTask, ...)`.
  Emits `Issue` + `BoardIssue` (board id = `ctx.scope.domain_id()`) + one
  `IssueAssignee` per assignee; for INCIDENT type also emits `Incident`
  (`table="boards"`, `scope_id` = board id) + `IncidentAssignee` rows. Issue and
  Incident share the task's `domain_id()`.

**Supporting change:** added an `re.IGNORECASE` `@validator`
(`compile_case_insensitive`) to `ClickUpScopeConfig` in `clickup/models.py` so tag
classification is case-insensitive (REQ-4.2, tech design §1.3); empty/missing patterns
normalize to `None`.
