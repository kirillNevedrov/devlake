## Objective

Implement `clickup/api.py`: the `ClickUpAPI` client with auth, the custom
`ClickUpPaginator`, and the response hooks for error handling and rate limiting. Provides
the request layer used by the stream (T6) and the plugin (T7).

## Files

- **Create** `backend/python/plugins/clickup/clickup/api.py`.

## Implementation notes

- Base URL from connection (`https://api.clickup.com/api/v2`); auth header
  `Authorization: <token>` with **no** `Bearer` prefix (tech design §1.4).
- Endpoint methods needed by callers: `GET /team`, `GET /team/{id}/space`,
  `GET /space/{id}/folder`, `GET /folder/{id}/list`, and the tasks endpoint with query
  params `order_by=updated&reverse=true&include_closed=true&subtasks=true&page&date_updated_gt`.
- `ClickUpPaginator`: ClickUp uses 0-indexed `page`, 100 tasks/page, stop on
  `last_page: true` (tech design §2.2, §1.4).
- Hooks: `handle_error` raising `pydevlake.api.APIException` on HTTP ≥ 400;
  `pause_if_too_many_requests` for HTTP 429 (sleep `Retry-After`, retry) — follow the
  framework hook pattern used in `azuredevops/api.py`.
- Mirror `azuredevops/api.py` structure and the ASF header.

## Definition of Done

- `import clickup.api` works; client instantiates from a `ClickUpConnection`.
- Unit tests (against recorded/fixture responses, no live calls): paginator advances
  pages and stops on `last_page`; `handle_error` raises `APIException` on a 4xx; auth
  header is set without `Bearer`.
- No regression to existing plugins.

### Deviations / notes

- `handle_error` and `pause_if_too_many_requests` (HTTP 429 → sleep `Retry-After`,
  retry) are **inherited from the framework base `pydevlake.api.API`** — azuredevops
  relies on the same base hooks rather than redefining them, so `ClickUpAPI` does not
  re-declare them. The task notes describe behavior that the base class already provides.
- `ClickUpPaginator.get_items` returns `None` for non-task responses (teams / spaces /
  folders / lists have no `tasks` key), which the framework treats as unpaginated —
  exactly the intended behavior for those single-page endpoints.
- `get_next_page_id` derives the next page from the request's current `page` query arg
  (`current + 1`) because ClickUp responses do not echo the current page number.
