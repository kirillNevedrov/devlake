## Objective

Register ClickUp as a selectable plugin in the config-UI so the whole setup (connection,
folder selection, scope config) can be done from the web interface. Pure frontend; no
dependency on the Python backend code.

## Files

- **Create** `config-ui/src/plugins/register/clickup/`:
  - `config.tsx` — `IPluginConfig` (`plugin:'clickup'`, `name:'ClickUp'`, icon, `sort`,
    connection fields `name`/token/`proxy`/`rateLimitPerHour`, `dataScope` miller-column
    Spaces→Folders, `scopeConfig` entities `['TICKET','CROSS']` + transformation fields).
  - `transformation.tsx` — Collapse panel with the three regex inputs
    (`issueTypeIncident`, `issueTypeBug`, `issueTypeRequirement`).
  - `assets/icon.svg`
  - `index.ts` — re-exports.
- **Modify** `config-ui/src/plugins/register/index.ts` — register `ClickUpConfig`.
- **Modify** the scope-config form (`scope-config-form/index.tsx`) — wire the ClickUp
  transformation panel via `plugin === 'clickup'`.

## Implementation notes

- Reuse built-in connection field components and the standard miller-column data-scope
  browser — no custom data-scope renderer (tech design §2.1).
- Mirror the existing `asana` / `linear` register packages for the regex transformation
  panel pattern and file layout.
- Field keys (`issueTypeIncident`, etc.) must match the backend scope-config field names
  from T2 so saved values round-trip.

## Definition of Done

- ClickUp appears in the plugin list with name + icon; the config-UI builds/lints
  cleanly.
- Connection form shows name/token/proxy/rate-limit; scope-config form shows the three
  regex inputs.
- No other plugin's registration is broken.
